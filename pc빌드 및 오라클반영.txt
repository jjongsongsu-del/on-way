< DB 넣기 >
PC에서 다시 생성하세요.

docker exec badagil-postgres pg_dump -U badagil -d badagil `
  -Fc `
  -t public.vessel_detail `
  -f /tmp/vessel_detail_seed.dump

PC로 복사:
docker cp badagil-postgres:/tmp/vessel_detail_seed.dump C:\dev\sea-load\vessel_detail_seed.dump

서버로 전송:



먼저 서버에 dump 파일이 있는지:
ls -lh /home/opc/sea-load/vessel_detail_seed.dump

컨테이너 안으로 복사:
docker cp /home/opc/sea-load/vessel_detail_seed.dump badagil-postgres-prod:/tmp/vessel_detail_seed.dump

컨테이너 안 파일 확인:
docker exec badagil-postgres-prod ls -lh /tmp/vessel_detail_seed.dump

복원 실행:
docker exec badagil-postgres-prod pg_restore -U badagil -d badagil \
  --data-only \
  -t vessel_detail \
  /tmp/vessel_detail_seed.dump


다시 건수 확인:

docker exec badagil-postgres-prod psql -U badagil -d badagil -c "select count(*) from vessel_detail;"
만약 pg_restore에서 “relation already exists” 같은 메시지가 나오면 무시해도 되지만, “0 rows”면 복원이 안 된 겁니다. 그때는 아래처럼 테이블명을 확인해 주세요:

docker exec badagil-postgres-prod pg_restore -l /tmp/vessel_detail_seed.dump | grep vessel_detail
여기 출력에 나오는 정확한 테이블명 기준으로 -t 값을 맞추면 됩니다.

서버에서 순서대로 실행해 주세요.

sudo dnf install -y dnf-plugins-core
sudo dnf config-manager --enable ol9_developer_EPEL
sudo dnf install -y certbot python3-certbot-nginx
설치 확인:

certbot --version
그 다음 HTTPS 인증서 발급:

sudo certbot --nginx -d seomttok.duckdns.org
만약 ol9_developer_EPEL 저장소가 없다고 나오면, 저장소 목록을 먼저 확인하세요.

sudo dnf repolist all | grep EPEL
그리고 보이는 이름이 예를 들어 ol9_developer_EPEL_modular 같은 식이면 그 이름을 enable 하면 됩니다.

추가로 Nginx가 아직 설치되어 있지 않으면:

sudo dnf install -y nginx
sudo systemctl enable nginx
sudo systemctl start nginx
인증서 발급 전에 Oracle Cloud 보안 목록과 서버 방화벽에서 80, 443이 열려 있어야 합니다.
Certbot이 도메인 검증할 때 http://seomttok.duckdns.org/.well-known/...로 접근하기 때문이에요.
