# 상태 코드 매핑

## 1. 운항상태 코드

| 표준 코드 | 사용자 표시 | 의미 | 앱 톤 |
| --- | --- | --- | --- |
| `NORMAL` | 정상운항 | 현재 정상 운항 또는 정상 출항 가능 | good |
| `SCHEDULED` | 운항예정 | 아직 출항 전이며 운항 예정 | neutral |
| `DELAYED` | 지연 | 출항 또는 도착 지연 | warning |
| `CANCELED` | 결항 | 해당 운항편 결항 | danger |
| `CONTROLLED` | 통제 | 기상/해상 상황 등으로 운항 통제 | danger |
| `COMPLETED` | 운항완료 | 출항 또는 운항 완료 | neutral |
| `UNKNOWN` | 정보 없음 | 외부 API 또는 원천 데이터에서 상태 확인 불가 | neutral |

## 2. 예보 코드

| 표준 코드 | 사용자 표시 | 의미 | 앱 톤 |
| --- | --- | --- | --- |
| `AVAILABLE` | 운항 가능 | 현재 예보 기준 운항 가능성이 높음 | good |
| `CAUTION` | 주의 | 기상 또는 해상 영향 가능성이 있어 확인 필요 | warning |
| `UNCERTAIN` | 불확실 | 판단 정보가 부족하거나 변동 가능성이 큼 | warning |
| `CONTROL_POSSIBLE` | 통제 가능성 | 통제 또는 결항 가능성이 있음 | danger |
| `UNAVAILABLE` | 운항 어려움 | 운항이 어려울 가능성이 높음 | danger |
| `UNKNOWN` | 정보 없음 | 예보 정보 확인 불가 | neutral |

## 3. 위험도 코드

| 표준 코드 | 사용자 표시 | 의미 |
| --- | --- | --- |
| `LOW` | 낮음 | 여행 가능성이 비교적 높음 |
| `MEDIUM` | 보통 | 주의와 재확인이 필요함 |
| `HIGH` | 높음 | 결항/통제 가능성에 대비해야 함 |
| `UNKNOWN` | 정보 없음 | 위험도 판단 불가 |

## 4. 외부 API 원문 매핑 원칙

공공데이터 API별 원문 상태값은 M3에서 실제 응답 샘플을 확보한 뒤 아래 우선순위로 표준화한다.

1. 원문이 정상/출항/운항 중이면 `NORMAL`
2. 원문이 예정/대기면 `SCHEDULED`
3. 원문에 지연이 포함되면 `DELAYED`
4. 원문에 결항이 포함되면 `CANCELED`
5. 원문에 통제/운항통제/기상통제가 포함되면 `CONTROLLED`
6. 원문이 완료/출항완료/입항완료면 `COMPLETED`
7. 원문이 비어 있거나 해석 불가하면 `UNKNOWN`

## 5. 화면 표시 원칙

- `CANCELED`, `CONTROLLED`는 홈 화면에서 최우선으로 노출한다.
- `DELAYED`는 다음 출항 시각과 함께 지연 사유를 표시한다.
- `UNKNOWN`은 장애로 보이지 않게 마지막 갱신 시각과 함께 "확인 필요" 문장을 붙인다.
- 예보는 "운항합니다"가 아니라 "운항 가능성이 높습니다"처럼 가능성 표현을 사용한다.
