# Google Play 데이터 보안 양식 초안

이 문서는 현재 앱 구현 기준의 초안입니다. Firebase Analytics, Crashlytics, 광고 SDK, 위치 권한, 로그인 기능 등을 추가하면 반드시 다시 작성해야 합니다.

## 데이터 수집 여부

현재 앱은 회원가입/로그인 없이 동작하며, 이름, 전화번호, 이메일, 사진, 연락처, 정확한 위치 권한을 요구하지 않습니다.

앱 기능 제공을 위해 사용자가 입력한 검색어, 출발지, 도착지, 선택한 섬/권역 등의 조회 조건이 서버 API 요청에 포함될 수 있습니다. 즐겨찾기, 최근 조회, 알림 설정 등은 기기 내 저장소에 저장되는 구조입니다.

## 데이터 공유 여부

개인 식별 목적의 사용자 데이터를 제3자에게 판매하거나 공유하지 않습니다.

공공 API 조회를 위해 서버가 공공데이터 API와 통신하지만, 앱 사용자를 식별하기 위한 개인정보를 외부 API에 전달하지 않습니다.

## 보안

- 앱과 서버 간 통신은 HTTPS를 사용합니다.
- 현재 API 기본 주소: `https://seaload.aodata.co.kr/api/v1`
- 사용자는 앱 내 즐겨찾기/최근 조회 데이터를 삭제할 수 있습니다.

## Play Console 답변 가이드

- 데이터 수집: 검색/조회 조건이 서버로 전송되는 점을 고려해 "예"로 답변하는 것이 보수적으로 안전합니다.
- 위치: 현재 위치 권한을 요청하지 않는다면 "수집하지 않음".
- 개인 정보: 이름, 이메일, 사용자 ID, 주소록 등을 앱에서 받지 않으면 "수집하지 않음".
- 앱 활동: 검색어/조회 조건을 서버 요청으로 처리하므로 "앱 상호작용" 또는 "기타 사용자 생성 콘텐츠/앱 활동" 해당 여부를 콘솔 항목 기준으로 확인.
- 진단: 별도 크래시/분석 SDK가 없다면 "수집하지 않음".
- 데이터 삭제 요청: 기기 내 데이터는 앱 삭제 또는 앱 내 삭제 기능으로 제거 가능. 서버 로그 삭제 요청 연락처는 개인정보 처리방침에 명시.

## 최종 확인 필요

- 서버 access log에 IP, User-Agent, 요청 경로가 저장되는지
- 운영 서버 로그 보관 기간
- Expo/React Native 런타임에서 추가 SDK가 자동 수집하는 데이터가 있는지
- 향후 푸시 알림, 위치 기반 추천, 계정 기능 추가 여부
