1. 추천 서비스 콘셉트
서비스 방향

여객선 이용자를 위한 실시간 운항·예보·항로·터미널 안내 앱

앱의 핵심 메시지는 이렇게 잡으면 좋습니다.

“오늘 배가 뜨는지, 언제 출발하는지, 어디서 타야 하는지, 내일도 운항 가능성이 있는지 한 번에 확인하는 여객선 이동 도우미”

특히 여객선은 버스·철도와 달리 기상, 통제, 항로, 기항지, 터미널, 결항 여부가 매우 중요합니다. 그래서 단순 스케줄보다 운항 가능성 + 실시간 상태 + 항로/노선 + 알림이 핵심입니다.

3. API 조합 평가

제시한 API들은 여객 중심 앱에 필요한 거의 모든 핵심 데이터를 갖고 있습니다.

API	앱에서의 역할
인천항만공사 여객터미널 실시간 운항정보	인천항 국제여객터미널 출입항 현황
KOMSA 여객선 운항상태 정보	당일 여객선 정상/통제/결항 등 상태
KOMSA 운항 스케줄 정보	날짜별 출항시간, 출항지, 항로, 선박, 정원
KOMSA 운항항로 정보	운항항로 코드·항로명 기준 데이터
KOMSA 내일의 운항예보	다음날 운항 가능성 안내
KOMSA 실시간 교통정보 조회	해상 교통량·혼잡도 등 실시간 교통정보
KOMSA 내일의 운항예보 상세	항로·선박 단위 상세 예보
KOMSA 운항노선 정보	기항지 순서, 기항지명, 노선 구성

인천항만공사 API는 국제여객터미널의 출항·입항 현황, 항로, 선박명, 출항시간, 터미널명 등을 실시간 XML 형식으로 제공하는 데이터입니다. KOMSA 운항 스케줄 정보는 연안여객선의 여객선명, 여객선코드, 일자, 출항시각, 출항지명, 면허항로명, 운항항로명, 통제사유, 여객정원수 등을 포함합니다. 운항항로 정보는 면허항로코드, 운항항로코드, 운항항로명 등을 제공하고, 운항노선 정보는 기항지 순번, 기항지 코드, 기항지명까지 포함하므로 항로 기반 화면을 구성하기 좋습니다.

4. 앱의 핵심 기능 제안
1) “오늘 배 뜨나요?” 홈 화면

여객 중심 앱의 첫 화면은 복잡하면 안 됩니다. 사용자가 가장 먼저 알고 싶은 것은 하나입니다.

오늘 내가 타려는 배가 정상 운항하는가?

홈 화면은 다음 구조가 좋습니다.

[오늘의 여객선 운항]

출발지 선택: 인천항 / 목포항 / 여수항 / 완도항 ...
도착지 선택: 백령도 / 덕적도 / 제주 / 울릉도 ...

오늘 운항상태
- 정상운항
- 지연
- 결항
- 통제
- 운항예정
- 운항완료

다음 출항
14:30  ○○호  인천 → 백령도

내일 운항예보
운항 가능 / 주의 / 불확실 / 통제 가능성

가장 좋은 UX는 사용자가 출발지와 도착지만 넣으면 오늘·내일 운항 여부를 바로 보여주는 방식입니다.

2) 실시간 운항상태 조회

KOMSA 여객선 운항상태 정보와 인천항만공사 실시간 운항정보를 함께 활용합니다.

주요 기능은 다음과 같습니다.

기능	설명
오늘 운항현황	정상, 지연, 결항, 통제, 완료 등 상태 표시
선박별 상태	선박명 기준 운항상태 확인
항로별 상태	특정 항로의 전체 운항현황 확인
터미널별 출항현황	인천항 국제여객터미널 등 터미널별 현황
통제사유 표시	기상, 안개, 풍랑, 정비 등 사유 제공
상태 변경 알림	정상 → 통제, 예정 → 출항 등 변경 시 푸시

단, 중요한 점이 있습니다. 2026년 4월 21일 공공데이터포털 공지에 따르면 KOMSA 여객선 운항상태 정보 API는 여객선 위치 데이터 연계 중단으로 복구 시까지 일시 중단 안내가 있었습니다. 앱 설계 시 이 API는 핵심 데이터로 쓰되, 장애·중단 가능성을 고려해 스케줄 정보, 내일 예보, 인천항만공사 데이터, 자체 캐시로 보완하는 구조가 필요합니다.

3) 운항 스케줄 조회

여객선 앱의 기본 기능입니다.

기능	설명
날짜별 시간표	오늘, 내일, 특정 날짜 출항시간 확인
출발지/도착지 검색	기항지 기준 검색
항로별 스케줄	인천-백령, 목포-홍도 등 항로별 조회
선박별 스케줄	특정 선박의 운항 일정 확인
여객정원 표시	선박 정원 정보 표시
통제사유 표시	운항 제한 사유 표시
캘린더 저장	출항시간을 개인 캘린더에 저장

운항 스케줄 API가 여객선명, 여객선코드, 일자, 출항시각, 출항지명, 항로명, 통제사유, 여객정원수 등을 포함하므로 앱의 시간표 기능에 가장 중요한 API입니다.

4) 내일의 운항예보

이 앱의 차별화 포인트입니다.

여행객 입장에서는 “지금 배가 뜨는지”보다 내일 여행을 가도 되는지가 더 중요할 때가 많습니다.

기능	설명
내일 운항 가능성	항로별 운항 가능/주의/통제 가능성 표시
상세 예보	항로·선박별 상세 운항예측
여행 위험도	낮음/보통/높음 형태로 단순화
기상 영향 안내	풍랑, 안개, 시정 악화 등 안내
전날 알림	내일 운항예보 발표 시 관심 항로 사용자에게 알림

KOMSA의 내일의 운항예보는 해양기상과 여객선 사정을 반영해 다음날 운항 가능 여부를 예측해 제공하며, 지역별·항로별·선박별 확인이 가능하다고 안내되어 있습니다. 다만 급격한 기상 이변이나 안개로 인한 시정 제한은 반영하지 못할 수 있다는 한계도 명시되어 있으므로, 앱에서도 “예보는 확정 운항정보가 아님”을 분명히 표시해야 합니다.

5) 항로·노선 지도

운항항로 정보와 운항노선 정보를 활용하면 단순 시간표 앱을 넘어 지도 기반 여객선 안내 앱으로 만들 수 있습니다.

기능	설명
항로 지도	출발지, 기항지, 도착지를 지도에 표시
기항지 순서	1번 기항지 → 2번 기항지 → 도착지 순서 표시
항로 상세	면허항로명, 운항항로명, 기항지 목록
섬 정보 연계	기항지 주변 관광지, 숙박, 교통 정보
현재 선택 항로 저장	자주 타는 항로 즐겨찾기

운항노선 정보 API는 기항지 순번과 기항지명을 포함하므로, “이 배가 어느 섬을 거쳐 가는지”를 보여주는 화면을 만들 수 있습니다.

6) 관심 항로·선박 알림

실사용성을 높이려면 알림 기능이 반드시 필요합니다.

알림 유형	예시
운항상태 변경	“인천 → 백령 항로가 정상운항에서 통제로 변경되었습니다.”
출항 임박	“○○호가 1시간 후 출항합니다.”
결항/통제	“내일 인천 → 덕적 항로 통제 가능성이 있습니다.”
예보 갱신	“관심 항로의 내일 운항예보가 업데이트되었습니다.”
지연 발생	“○○호 출항시간이 지연되었습니다.”
운항 완료	“○○호가 출항 완료되었습니다.”

이 앱의 핵심 가치는 “조회”가 아니라 내가 타려는 배에 문제가 생기면 먼저 알려주는 것입니다.

2) 여행 가능성 점수

내일의 운항예보와 실시간 운항상태를 일반 사용자 언어로 바꿔줍니다.

예시:

백령도 여행 가능성: 보통

- 오늘 운항: 정상
- 내일 예보: 주의
- 최근 항로 상태: 일부 지연
- 확인 필요: 출발 전 터미널 공지

주의할 점은 실제 예보와 다르게 확정적으로 말하면 안 된다는 것입니다. 표현은 “가능성”, “주의”, “확인 필요” 중심이 좋습니다.

백엔드가 필요한 이유

여객 앱은 반드시 백엔드를 두는 것이 좋습니다.

이유	설명
API 키 보호	공공데이터 인증키를 앱에 직접 넣으면 노출 위험
데이터 통합	KOMSA, 인천항만공사 API 구조가 다름
포맷 통합	XML, JSON+XML 혼재 데이터를 앱용 JSON으로 변환
캐싱	개발계정 트래픽 제한 대응
알림	운항상태 변경 감지는 서버에서 주기적으로 수행 필요
장애 대응	API 중단 시 마지막 정상 데이터를 안내 가능
즐겨찾기	사용자별 관심 항로 저장 필요

특히 KOMSA 일부 API는 개발계정 기준 트래픽이 100건으로 낮게 표시되어 있어, 앱에서 직접 호출하면 금방 한도에 걸릴 수 있습니다. 운항 스케줄 정보와 운항항로 정보 모두 개발계정 100건, 운영계정은 활용사례 등록 시 트래픽 증가 가능 구조로 안내되어 있습니다.

13. 결론

이 API 조합으로 앱을 만드는 것은 충분히 좋습니다. 오히려 앞서 말한 항만 물류 앱보다 사용자 타겟이 명확합니다.

다만 성공하려면 방향은 단순 조회가 아니라 다음과 같아야 합니다.

“여객선 시간표 앱”이 아니라, “섬으로 이동하는 사람을 위한 실시간 바다 교통 앱”

1차 MVP는 오늘 운항상태 + 시간표 + 내일 예보 + 관심 항로 알림만 잘 만들어도 실사용 가치가 있습니다. 이후 항로 지도, 섬 관광, 예매 링크, 가족 공유, 다국어 안내로 확장하면 충분히 경쟁력 있는 여객 중심 앱이 됩니다.
